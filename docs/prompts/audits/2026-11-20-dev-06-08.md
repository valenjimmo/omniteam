## Findings

### [MEDIUM] Trusted registration configuration accepts structures its consumers cannot handle

- Evidence: `configure_team_registration` accepts any JSON object no larger than
  100 KB and stores it without validating the shapes or members of `programs`,
  `questions`, or `agreements`
  (`supabase/migrations/202610010001_configurable_family_registration.sql:160-175`).
  The public form casts that value to `RegistrationConfiguration` and directly
  calls `.filter()`/`.map()` on those members
  (`src/app/register/[slug]/page.tsx:56-58,112-116`). The DEV-06 submission RPC
  likewise calls `jsonb_array_elements` and `jsonb_array_length` on those values
  and casts configuration booleans
  (`supabase/migrations/202611200001_family_registration_role_and_intake_validation.sql:128-159`).
  Current tests cover malformed answers against a valid configuration, but not
  direct configuration-RPC calls with malformed arrays, question types/options,
  IDs, or agreement members.
- Impact: an authorized owner or direct RPC caller can save configuration that
  makes the public registration route throw during rendering or makes all
  submissions fail at the trusted boundary. Closing and reopening registration
  does not repair the stored configuration.
- Minimal fix: add a forward migration that validates the complete supported
  configuration contract in `configure_team_registration` before storage.
  Require arrays for programs/questions/agreements; supported question types and
  scopes; non-empty unique IDs; correctly typed required/options fields; options
  for select types; and valid agreement IDs/booleans. Use the same shared
  constraints for existing-row preflight or provide a deterministic repair for
  invalid stored rows before adding any database constraint. Make the client
  fail closed with a readable unavailable/configuration message if legacy data
  is still malformed.
- Acceptance tests: direct RPC attempts with scalar/object collections,
  duplicate or empty IDs, unsupported types/scopes, missing or non-array select
  options, and malformed agreement flags are rejected without changing the
  prior configuration. A complete valid configuration saves, renders every
  supported question type, accepts a valid submission, and remains team-scoped.
  Include a legacy malformed-row migration/preflight case and an authenticated
  browser check that the route fails closed rather than crashing.
